# NetSec XAI Chat Implementation Plan

> **For agentic workers:** Use bounded implementation slices with explicit file ownership and verify their integrated effects. Steps use checkbox syntax for tracking.

**Goal:** Repair English generation and add a local chat that can display only approved app evidence and XAI guidance.

**Architecture:** Rust owns immutable contexts, dialogue history, allowed evidence and policy checks. The local model selects evidence IDs through constrained JSON; React renders the validated replies and their provenance. Model inference and research artifacts remain separate.

**Tech Stack:** Existing Electron, React/TypeScript, Rust, llama.cpp and pinned Qwen GGUF; no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-26-xai-chat.md`.

## Global constraints

- Default inference stays offline, CPU-only and credential-free; no model replacement or training.
- Preserve native detector/XAI calculations, research data, locked tests and the current theme.
- Missing language execution never yields a substitute answer labelled as LLM output.
- Only server-owned model observations and stored explanations may enter chat context.

## Review focus

- A prompt mentioning XAI while requesting unrelated output cannot introduce new displayable prose.
- Explanations from another model/row/context are rejected.
- Reset/context switch/runtime shutdown cannot restore late answers or leak orphan workers.
- Truncated, repeated or invalid model selections are rejected rather than silently repaired.
- Prediction-only and frozen live contexts clearly disclose their evidence limitations.
